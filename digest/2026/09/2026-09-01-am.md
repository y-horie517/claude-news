## ① 今日の型 — `/batch`でファンアウト移行を任せる

昨日の朝刊では、大量ファイルの移行作業を`claude -p`のループで並列化する方法（`for`は逐次実行、本当に並列にするには`xargs -P`が必要）を紹介しました。Claude Codeにはこの手順そのものを引き受ける組み込みコマンド`/batch`があります。

gitリポジトリ内で`/batch <指示>`を実行すると、Claudeが変更内容を**5〜30体のサブエージェント**（親とは別のコンテキストで動く子セッション）に自動分割します。各サブエージェントは自分専用の**worktree**（同じリポジトリを別ディレクトリにチェックアウトした作業コピー）で作業し、完了するとそれぞれがプルリクエストを作成します。ファイル一覧を自分で作ってスクリプトを書く手間や、worktreeの管理・PR作成を自分でやる手間が減ります。

```mermaid
flowchart LR
  A["対象ファイル一覧を用意"] --> B["/batch \"指示文\" を実行"]
  B --> C["5〜30体のサブエージェントに自動分割"]
  C --> D["各サブエージェントが専用worktreeで作業"]
  D --> E["サブエージェントごとにPRを作成"]
```

そのまま試せるプロンプト例（Next.jsプロジェクトで、複数コンポーネントの相対importをエイリアスに統一する例）:

```
/batch src/components 配下の相対import（../../lib/... のような形）を
すべて @/lib/... のエイリアス形式に書き換えて。ファイルごとに1つの
プルリクエストを作成して。
```

対象ファイル数が少ないと、単一セッションで処理されて分割が起きないこともあります。まず数ファイルで試し、挙動を確認してから本番の対象に広げるのがおすすめです（`/batch`と手動`xargs -P`ループの使い分けは、PRを個別レビューしたいか・一括で流したいかで選ぶとよいでしょう）。

出典: [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices)

## ② すぐ効くTIPS

### 1. `/statusline`でコンテキスト残量を常時可視化する
コンテキストが埋まるほど回答の精度は落ちますが、`/context`を都度打たない限り残量には気づきにくいものです。`/statusline`は自然言語の指示から表示用スクリプトを`~/.claude/`に生成し、設定まで自動で済ませてくれます。
実行例:
```
/statusline show model name and context percentage with a progress bar
```

### 2. `claude agents`（Agent view）で複数のバックグラウンドセッションを1画面から見る
調査や修正を複数並行で走らせると、ターミナルを行き来する分だけ気が散ります。Agent viewは「Needs input / Working / Completed」といった状態別に一覧表示し、`Space`キーで最新の出力だけを覗ける「Peek」機能があります。まだresearch preview（研究段階の先行公開）のため、操作方法は今後変わり得ます。
実行例: シェルから直接バックグラウンドセッションを投入できます。
```
claude --bg --name "flaky-test-fix" "investigate the flaky test"
```
その後`claude agents`を起動すると、名前つきで一覧に現れます。

### 3. サブエージェントの`tools`と`model`をfrontmatterで絞る
`.claude/agents/`配下のサブエージェント定義は、使わせるツールと使うモデルを明示的に絞れます。何でもできるサブエージェントは事故りやすく、単純作業に高価なモデルを使うのはコストの無駄です。
実行例:
```markdown
---
name: security-reviewer
description: Reviews code for security vulnerabilities
tools: Read, Grep, Glob, Bash
model: opus
---
You are a senior security engineer. Review code for:
- Injection vulnerabilities (SQL, XSS, command injection)
- Authentication and authorization flaws
```

## ⑤ きょうのミニ課題

**`/batch`で小さな一括置換を試す**

前提: Next.jsプロジェクトのgitリポジトリで、`git status`がクリーンな状態。同じパターンの重複が3〜5ファイル程度ある状態（例: 複数コンポーネントに残る`console.log`、統一されていない相対importなど）を用意する。

1. 置き換えたいパターンを含むファイルを3〜5個見つけておく。
2. `/batch "〇〇を△△に置き換えて"`のように指示を出し、何体のサブエージェントが起動し、worktreeがいくつ作られたかを観察する。
3. 生成された差分・プルリクエストの内容を確認し、昨日の`xargs -P`ループと比べて自動化された部分（worktree管理・PR作成）と、逆に自分で判断が必要だった部分をメモする。

確認方法: 各ファイルの変更が意図通りで、worktree・PRが正しく作られていれば合格です。対象ファイルが少なく分割が起きなかった場合は、その挙動自体を観察結果として記録してください。答え合わせは今夜の夕刊で。
