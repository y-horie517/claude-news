# 朝→夕 の引き継ぎメモ

朝刊エージェントがここに「本日のミニ課題」と模範解答の要点を書き、夕刊エージェントが読んで答え合わせを書きます。
夕刊エージェントは答え合わせを書いたあと、このファイルを次の日のために空のテンプレートに戻すこと。

---

- date: 2026-08-28
- 課題: いま取り組んでいる Next.js のコンポーネントか API route を1つ選び、(1)Claude Codeに「まず失敗するテストを書いてから実装し、テストを実行して通す」よう指示する、(2)実装完了後に「サブエージェントを使ってこの差分を要件と照らし合わせ、抜け漏れだけ報告して」と続けて指示する、(3)サブエージェントの指摘のうち直すべきものと無視してよいものを自分で判断する、という一連の「検証つきで任せる」ワークフローを体験する。所要15分。
- ねらい: Claude に実装を任せきりにするのではなく、(a)機械的に合否が出るチェック（この課題ではテスト）と、(b)人間の代わりに一次チェックする独立したレビュー（サブエージェントによる差分レビュー）の2段構えを組み込むと、見張っていなくても間違いに気づける、という型を手で覚えること。朝刊①のプロンプト例をそのまま使えば実行できる設計にした。
- 模範解答の要点:
  - Claude に「失敗するテストを先に書く」よう指示すると、実装前に期待動作が固定される（TDD的アプローチ）。テストが red → 実装 → green の順で進んだか確認する。
  - サブエージェントレビューの指示は「要件との照合」「エッジケースの網羅」「範囲外の変更混入チェック」の3点に絞ると、スタイルの好みなど枝葉の指摘に埋もれずに済む。
  - サブエージェントの指摘は「correctnessに関わるものだけ拾う」が正解。過剰な抽象化や不要な防御的コードを求める指摘は無視してよい（Best practicesのCalloutにも同旨の注意がある）。
  - 出典: https://code.claude.com/docs/en/best-practices の "Give Claude a way to verify its work" と "Add an adversarial review step" の節がそのまま模範解答に当たる。
- ハマりどころ:
  - テストを書かせる指示が曖昧だと（例:「テスト書いて」だけ）、Claude が何を確認すればテストが十分かを自己判断してしまい、エッジケースが漏れやすい。対象のエッジケース（例:ログアウト状態、空配列、境界値など）を明示させることが鍵。
  - サブエージェントへの指示が広すぎる（例:「レビューして」だけ）と、スタイルの好みまで指摘してきて「直すべきもの」が埋もれる。「correctnessと要件充足だけ報告して」のように範囲を絞らないと過剰な指摘が返る。
  - Next.js の API route はサーバー/クライアント境界が絡むため、テストの実行環境（jest/vitest の設定など）が整っていないとテスト自体が動かせないことがある。事前に `npm test` が通る状態か確認しておくとつまずかない。
