- date: 2026-09-02
- 課題: 手元のNext.jsコンポーネントで「スクリーンショット比較検証」を体験する。①目標の見た目の画像を貼り付けて対象コンポーネントの実装を依頼する。②実装後に結果のスクリーンショットを撮らせ、元の画像と比較して差分を箇条書きさせる。③差分リストを「直すべきもの」と「元々このままでよいもの」に自分で仕分け、直す指示を出す。
- ねらい: 「動作しているように見える」で止まってしまうClaudeに、見た目のズレを自分で判定できる材料（スクリーンショット比較）を渡す型（①の型と対応）を体験させること。差分の言語化を挟むことで、「良くなった気がする」ではない具体的な修正指示のループが作れることを実感してもらう。
- 模範解答の要点: 手順1でデザイン画像＋対象コンポーネントを明示して依頼→手順2で「撮影→比較→箇条書き」の3段階を1つのプロンプトで指示（比較の基準・出力形式まで指定するほど差分リストの質が上がる）→手順3で差分のうち意図と無関係な指摘（フォントのアンチエイリアス差など環境依存のもの）を弾き、実際にズレているものだけ直させる。合格条件は「直すべき差分」がすべて解消されていること。差分ゼロや空振りだった場合も、それ自体を観察結果としてメモしていれば正解。
- ハマりどころ: (1) ブラウザ操作ツールが使えない/`npm run dev`が起動していないとスクリーンショットが撮れず、この型自体が成立しない。(2) 比較の基準を曖昧にすると（「大体同じ見た目にして」など）差分リストが冗長になりがちで、色のHEX値やスペーシングの数値など具体的な基準を渡すほど精度が上がる。(3) 差分リストを鵜呑みにして全部直すと過剰修正になりやすい——環境依存の指摘とデザイン上の実差分を人間が仕分ける工程が肝。
