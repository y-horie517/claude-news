# 朝→夕 の引き継ぎメモ

朝刊エージェントがここに「本日のミニ課題」と模範解答の要点を書き、夕刊エージェントが読んで答え合わせを書きます。
夕刊エージェントは答え合わせを書いたあと、このファイルを次の日のために空のテンプレートに戻すこと。

---

- date: 2026-08-31
- 課題: Stop hookで検証を強制してみる。前提はNext.jsプロジェクトで `npm run lint`（または `npm test`）が通る状態。手順は (1) Claude Codeに「lintが通るまでターンを終了しないStop hookを `.claude/settings.json` に書いて、`/hooks` で内容を確認して」と依頼する (2) 生成されたhookの中身（コマンドと終了コードの扱い）を理解する (3) Claudeに「意図的にlintエラーになる小さな変更をして」と頼み、Stop hookがブロックして自己修正するループを観察する。確認方法は、Stop hookに阻まれてClaudeが修正を繰り返し最終的にlintが通って正常終了すること、hookの中身から失敗時の挙動を自分の言葉で説明できること。
- ねらい: Stop hookが検証を「決定的に」強制する仕組みを体感し、CLAUDE.mdのような助言的な指示との違いを理解する。あわせて、朝刊①型・②TIPS1で扱った「Stop hookは8回連続ブロックで強制的に上書きされる」という制限も体感・理解する（ループが自然に終わらない設計だと気づかず放置しないための知識）。
- 模範解答の要点:
  - hookは `.claude/settings.json` の `hooks.Stop` に、`type: "command"` として lint/test コマンドを実行するエントリを書く形になる（Claude Codeが `/hooks` UIで生成・確認できる）。
  - コマンドが非ゼロの終了コード（exit code 2など、ブロックを意味する終了コード）を返すとClaude Codeはターンを終了させず、Claudeにフィードバックが返って自己修正が続く。ゼロ終了（lint成功）でターンが正常に終わる。
  - 「意図的にlintエラーになる変更」をさせると、1回目の `npm run lint` がhookとして走り失敗 → Claudeが修正 → 再度lintが走る、という往復が観察できるはず。
  - この往復は無限ではなく、Claude Codeは同じ場面でhookが8回連続でブロックすると、hookを上書きしてターンを終了させる仕様。今日の課題ではlintエラーは1〜2回の修正で解消するはずなので、8回に達することは通常ない。達した場合はhookのコマンド自体が壊れている（パス間違い・コマンド不在など）可能性が高い。
- ハマりどころ:
  - hookのコマンドが `npm run lint` の実行ディレクトリを想定通りに解決できず（プロジェクトルート以外から実行される等）、常に失敗し続けるケース。この場合8回で強制終了になるので、その挙動自体は「仕様通り」であり、バグではない。
  - `/hooks` で見た設定がClaudeの生成したJSONの構文ミスで読み込まれていないケース（設定が効いていない＝lintを壊してもStop hookが一切反応しない）。
  - Next.js標準の `next lint` はwarningでは非ゼロ終了しないことがあるため、「意図的に壊す」変更はerror相当（未使用変数などstrictモードで弾かれるもの）にする必要がある。
