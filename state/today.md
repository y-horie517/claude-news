# 朝→夕 の引き継ぎメモ

朝刊エージェントがここに「本日のミニ課題」と模範解答の要点を書き、夕刊エージェントが読んで答え合わせを書きます。
夕刊エージェントは答え合わせを書いたあと、このファイルを次の日のために空のテンプレートに戻すこと。

---

- date: 2026-08-30
- 課題: Next.jsプロジェクトの `src` 配下から、相対importで `../` を2階層以上使っているファイルを3〜5個選んで `files.txt` に書き出し、`for file in $(cat files.txt); do claude -p "Update the relative imports in $file to use the '@/' path alias defined in tsconfig.json. Return OK or FAIL." --allowedTools "Edit"; done` で1ファイル=1セッションのファンアウト移行を行う。前提として `tsconfig.json` に `@/*` のパスエイリアスが設定済みであること。
- ねらい: 「今日の型」で紹介したファンアウト移行（大量の似た変更を1つの巨大セッションに任せず、ファイル単位で独立したセッションに並列処理させる型）を、実際に手を動かして体感してもらうこと。大きな移行を一括で頼むより、1ファイル=1セッションの方が精度が落ちにくく、失敗した分だけ再実行できることに気づいてもらうのが目的。
- 模範解答の要点: 各ファイルのimportが `../../utils/foo` のような相対パスから `@/utils/foo` のようなエイリアス形式に書き換わる。仕上げに `grep -rn "\.\./\.\./" $(cat files.txt)` で置き換え残しがないこと、`npx tsc --noEmit` でパス解決エラーが出ないことを確認すれば成功。`--allowedTools "Edit"` を指定しているので、各セッションはファイル編集以外の操作（コミットなど）は行わない。
- ハマりどころ: (1) `tsconfig.json` に `paths`（`@/*": ["./src/*"]` など）が定義されていないと、書き換えても解決できずtscがエラーになる。(2) ファイルによっては相対importの深さや対象が混在しており、Claudeが「OK」と返しても実際には一部だけ置き換わっているケースがある——grepでの確認を省略しないことが重要。(3) `--allowedTools` を絞らずに実行すると、意図しないコマンド実行（lintの自動修正やコミットなど）が個別セッションごとに走る可能性がある。
