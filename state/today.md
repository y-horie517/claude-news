# 朝→夕 の引き継ぎメモ

朝刊エージェントがここに「本日のミニ課題」と模範解答の要点を書き、夕刊エージェントが読んで答え合わせを書きます。
夕刊エージェントは答え合わせを書いたあと、このファイルを次の日のために空のテンプレートに戻すこと。

---

- date: 2026-08-29
- 課題: 手元のNext.jsプロジェクトで小さめの機能（一覧ページに検索フィルタを1つ追加する、既存フォームにバリデーションを1件追加する、など）を選び、「探索→計画→実装→コミット」の型（Plan Mode）を実際に体験する。手順は①`claude --permission-mode plan`起動 or `Shift+Tab`でPlan Modeへ ②対象ファイルと既存の実装パターンを調べさせる ③実装計画を作らせる ④`Ctrl+G`で計画をエディタで開き、抜けている考慮点（エラー時の表示、空文字列の扱いなど）を自分で1行書き足す ⑤Plan Mode解除→実装→`npm run build`/`npm run lint`で確認。
- ねらい: 「いきなり実装させる」と「探索・計画を分離してから実装させる」の体験差を、実際に手を動かして比較させること。特にCtrl+Gで計画を自分の目でレビューし、Claudeが見落としていた考慮点を人間が足す、という「計画を読む価値」を体感させるのが主眼。
- 模範解答の要点: Plan Modeで洗い出した計画には、典型的にはハッピーパスの実装手順しか書かれず、エラー時のUI表示・空値/未入力時の挙動・既存コンポーネントとの命名/スタイルの整合性などが漏れやすい。Ctrl+Gで開いた計画に、読者自身がその種の考慮点を1行足せていれば模範解答としては十分。実装後は、足した考慮点が実際のコードに反映されているか（例: エラー分岐が実装に存在するか）を確認できていれば合格。`npm run build`/`npm run lint`が通っていることも確認ポイント。
- ハマりどころ: (1) Plan Modeに入ったつもりが通常モードのままで、いきなり編集が走ってしまうケース（ステータス表示「⏸ plan mode on」を確認していないと起きやすい）。(2) `Ctrl+G`がターミナルやOSのショートカットと衝突して開かないケース（エディタが`$EDITOR`環境変数で設定されているか確認）。(3) 対象タスクが「一文で説明できる」レベルの小さすぎる変更だと、Plan Modeのオーバーヘッドの方が目立ってしまい、型のメリットを実感しづらい——公式ガイドも小さすぎるタスクにはPlan Modeを勧めていない点に触れておくとよい。
