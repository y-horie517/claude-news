# スタイルガイド

このファイルは記事の「品質の定義」です。エージェントは執筆前に必ず全文を読むこと。

## 読者プロフィール

- 日本語話者。Claude Code を日常的に使って開発している（主に Web / Next.js）。
- 関心の重点は **(A) Claude Code での開発** と **(B) チーム・業務への展開**。この2つに寄せる。
- Claude API / SDK / claude.ai チャットの話題は「開発や業務展開に効くとき」だけ取り上げる。
- Claude Daily は1日1号。12〜15分で読み切れる分量（日本語 4,500〜6,000字程度）。

## 文体

- **ですます調**。断定できることは断定し、曖昧なことは曖昧だと書く。
- 専門用語は**初出時に1行で説明**する（例:「サブエージェント（親とは別のコンテキストで動く子セッション）」）。
- 煽らない。「革命的」「爆速」などの誇張表現は使わない。
- 箇条書きに逃げず、**なぜそうするのか**を1〜2文で必ず添える。
- コマンド・設定・プロンプト例は**そのままコピペして試せる**形で書く。断片ではなく完全な形にする。

## 図の作法

- 図は**メカニズムを示すためのもの**。飾りの図・情報量ゼロの図は入れない。
- 構造・フロー・関係・時系列は **Mermaid** を使う。Artifact も GitHub も追加ライブラリなしで描画される。
  - Markdown 側: ```mermaid フェンス
  - Artifact HTML 側: `<pre class="mermaid">` ブロック
  - 使う種類: `flowchart` / `sequenceDiagram` / `timeline` / `mindmap` / `stateDiagram-v2`
- 「A と B の違い」「手順の対比」「設定値の一覧」は**表**にする。Mermaid で無理に描かない。
- Mermaid のノードラベルに `()` `[]` `:` を裸で入れると壊れるので、`["テキスト"]` のように必ずダブルクォートで囲う。
- **1号あたり最低3枚**。「① ベストプラクティス」と「② 深掘り連載」には必ず1枚ずつ入れる。

## コードの作法

「① ベストプラクティス」は**図とコードで示す節**です。文章だけで終わったらその日の看板は不成立です。

- **そのまま実行・貼り付けできる完全な形で書く。** 断片や省略記号（`...`）で逃げない。
- 設定ファイルは**パスを必ず添える**（`.claude/settings.json` / `.claude/skills/<name>/SKILL.md` / `CLAUDE.md` など）。JSON は抜粋ではなくそのファイルとして妥当な全体を載せる。
- コマンドは実際に打てる1行にする。プレースホルダを使うときは、直後に「`<name>` はスキル名」のように何を入れるか書く。
- **推測でキー名・オプション名・バージョンを書かない**（ガードレール2の再掲）。一次情報で確認できないものは、その論点ごと落とす。
- **アンチパターンは「なぜ失敗するのか」まで書く。** 「〜しないこと」の列挙で終わらせない。可能なら失敗する側のコードも短く並べて対比させる。
- ②③⑦でもコードを出してよいが、必須なのは①。

## 品質ガードレール（違反したら書き直す）

1. **出典URLを必ず添える。** 事例・新機能・数値には出典を付ける。裏が取れない話は書かないか、「未確認」と明示する。
2. **推測でバージョン番号・機能名・料金・オプション名を書かない。** 必ず一次情報（公式ドキュメント / CHANGELOG / 公式ブログ）で確認する。確認できなければその話題を落とす。
3. **既出トピックを繰り返さない。** `state/covered-topics.md` に載っているものは扱わない。触れる必要があるときは過去号へのリンクだけにする。
4. **ネタがない日は正直に書く。** 「本日は特筆すべき新機能の発表はありませんでした」と書いてよい。埋めるために薄い話題を捏造しない。
5. **手元で試せることを優先する。** 抽象的な心構えより、今日のうちに実行できる具体を書く。

## 原稿は2つの形で作る（混ぜない）

同じ内容を**別々に2回書きます**。片方をコピーしてもう片方にしないこと。

| 出力先 | 形式 | ルール |
|---|---|---|
| `digest/YYYY/MM/YYYY-MM-DD.md`（GitHub アーカイブ） | **純粋な Markdown** | `<div>` `<p class="src">` `<h3>` などの **HTML タグを一切入れない**。見出しは `###`、囲みは引用 `>`、出典は `出典: [タイトル](URL)`、図は ```mermaid フェンス |
| Artifact の HTML | **テンプレートのクラス構造** | `template/COMPONENTS.md` のクラスを使う。Markdown 記法（`##` や `**`）を書かない |

GitHub 上で `<div class="item">` がそのまま文字として見えてしまうと台無しです。**Markdown を書き終えたら `grep -n "<div\|<p class\|</content" ファイル` で確認**し、1件でも出たら直してください。

## 一次情報の見分け

- 一次情報: `docs.claude.com` / `anthropic.com/news` / `anthropic.com/engineering` / `github.com/anthropics/*`
- 二次情報（要注意）: 個人ブログ、Zenn/Qiita、Reddit、X。**事例としては価値があるが、機能の仕様の根拠にはしない。**
- 二次情報を引くときは「〜という報告があります（出典）」と伝聞であることを明示する。
